# RoomieMatch upgrade — 2026-11-25

## What changed
- Reworked occupation detection into a broader, higher-precision role recognizer covering technology, healthcare, education, finance, trades, government, logistics, HR, customer support, real estate and more.
- Added evidence snippets and a phrase-match-strength indicator so users can see which words caused an occupation to be filled.
- Removed weak occupation guesses from the synthetic-trained multiclass model. If the description does not contain a clear role phrase, the app leaves the profession blank rather than confidently inventing one.
- Fixed stale auto-filled occupation values: when a user edits their bio and no role is detected, the previous auto-filled value is cleared unless the user manually edited the profession field.
- Added a persistent light/night mode toggle, including on the sign-in screen.
- Hid scrollbar visuals without disabling scrolling.
- Replaced any notion of an online/offline action control with small connection-transport text below the contact's name in the chat header. This describes the app's WebSocket connection, not the other person's presence.
- Disabled automatic demo-account message replies and removed generated reply chips from the chat UI. Incoming messages never trigger a response; the user writes and sends every message.
- Added regression cases for more occupations and no-guess behaviour.

## Validation
- JavaScript syntax checks passed for the modified client and server files.
- Python bytecode compilation passed for modified AI files.
- Focused occupation-lexicon checks passed for data analyst, frontend developer, electrician, civil servant, designer and pharmacist.
- Full Python ML suite could not run in this environment because Flask is not installed (`ModuleNotFoundError: flask`). Run `pip install -r ai-service/requirements.txt` then `npm run ai:test` locally.


## Active-learning / ML project upgrade
- Added per-profile Good fit / Not for me feedback controls to discovery cards.
- Persisted explicit feedback in both JSON and MongoDB storage, one current label per user/candidate.
- Included feedback from real accounts in supervised retraining alongside genuine accept/decline decisions; demo-account outcomes remain excluded.
- Disabled the automatic smart-reply suggestion surface in chat; incoming messages never trigger a generated reply or pre-filled response. The user must compose and send every message.
- Expanded occupation evidence patterns for degree context, software engineering students, public-sector/armed-forces roles, analytics, counseling, media and trades.
- Added occupation regression tests for common job titles, degree-vs-employment distinction, traceable evidence and no-guess behaviour.
- Added context checks so a job mentioned as a relative/friend's role, a negated identity ("I am not a doctor"), or an aspiration ("I want to become a developer") is not assigned to the user; self-occupation later in the same sentence is still recognized.
- Added an AI Lab page with live service health, model architecture, training-set counts, held-out AUC/NDCG/F1/extraction metrics, and an explicit warning when evaluation is still synthetic-only.
- Updated `npm run ai:test` to discover both the existing ML pipeline suite and the new occupation regression suite.
